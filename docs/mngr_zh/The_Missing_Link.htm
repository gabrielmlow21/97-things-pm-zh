缺少的那一环

Paul Waggoner, MBA, PMP, MCSE, CHP, CHSS Waukee, Iowa, USA

软件项目经理都同意，最难的挑战之一，是让团队成员真正投入项目的细节，并掌握好自己的任务和进度。他们明白，团队成员夹在两种工作之间：一边是日常的运营工作，比如处理日常事务、排除故障、协调部门的事、回复各种沟通；另一边是有时间要求的项目开发工作。

被选进项目团队，一开始可能会被看作一种肯定，但很多开发人员觉得，参与项目会让他们分心，没法好好做日常工作。到了紧要关头，开发人员可能会直接说，对他/她来说，日常维护和支持自己负责的系统，比做项目任务更重要。

作为项目经理，如果你的工作不能、或者不被给予明确的优先地位，你的第一反应会是觉得这个人不适合留在团队。可是大多数公司的业务专家（SME）人数有限，所以换人或找一个更投入的人，可能根本不现实。

下面是几个简单的建议，可以帮你解决这个问题：

  • 确保各级管理层都支持项目的目标。
  • 修改业务专家的职位说明，加上“根据需要担任各项目的团队成员”，而不是只写“完成其他分配的工作”。
  • 请管理层和人事部门强调这一点，并确保所有主管在以后的绩效评估中，把项目工作的成绩看得很重。
  • 每个新项目开始时，由软件项目经理、部门经理或主管、发起人，或另一位重要的相关方，发一封个人化的邀请，请每位成员加入项目。这封信或邮件应该说明项目的主要目标，以及这位成员的主要职责。
  • 宣布项目顺利完成时，每位成员都会得到一张可以装框的表扬证书。并说明证书的副本会放进他/她的人事档案，在季度绩效评估时参考。
  • 部门经理的上司应该明确表示，项目对推进公司目标的作用，比日常 IT 工作更重要。
  • 高层应该特别要求部门经理，帮项目成员定期空出时间做项目工作，就算他的日常工作要暂时交给 IT 部门的其他人。

要让大家清楚知道：成功参与项目的人，是在为公司“多走一里路”，应该得到肯定和奖励。不管项目大小，成功参与的人都应该被特别表扬。就像敏捷圈子里说的，这能把“做得到的事”放在正确的位置上，让公司目标和员工的动力保持一致。
