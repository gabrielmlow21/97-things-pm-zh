缺失的一环

Paul Waggoner, MBA, PMP, MCSE, CHP, CHSS Waukee, Iowa, USA

软件项目经理们一致认为，他们面临的最困难的挑战之一，就是让团队成员恰当地投入到项目的细节中，并掌控好分配给他们的任务和进度。他们明白，团队成员在两类工作之间左右为难：一类是例行的运营职责，比如处理日常工作、排除故障、协调部门事务、回复日常沟通；另一类是有时间要求的项目开发工作。

虽然被选入项目团队起初可能被视为一种赞许，但许多开发人员觉得参与团队工作会严重分散他们对日常职责的注意力。到了紧要关头，开发人员可能会公开承认，对他/她来说，日常维护和支持所负责的系统，比完成项目任务更重要。

作为项目经理，如果你的工作不能、或者不愿被赋予明确的优先级，你的第一反应会是断定这个人不适合待在团队里。然而，大多数组织中的主题专家（SME）数量有限，所以更换团队成员或找一个更投入的人可能并不现实。

下面是几条有助于解决这个问题的简单建议：

  • 确保所有管理层级都支持项目的目标和目的。
  • 修改主题专家的职位描述，加入“根据需要在各个项目中担任团队成员”，而不是“履行所分配的其他职责”。
  • 让管理层和人力资源部门强调这一变化，并确保所有主管在今后的绩效评估中给予项目活动成果很高的权重。
  • 在每个新项目开始时，由软件项目经理、部门经理或主管、发起人或另一位关键干系人发出一份个性化的通知，邀请每位团队成员参与项目。这封信或电子邮件应说明所承担项目的高层目标，以及这位团队成员的高层职责。
  • 宣布在项目圆满结束时，每位团队成员都将获得一份可以装裱的表彰与成就证书。注明证书的副本将放入他/她的人事档案，供季度绩效评估时参考。
  • 部门经理的上级应该明确表示，项目对推进组织目标的作用，甚至比例行的信息技术（IT）任务更重要。
  • 高管应专门要求部门经理帮助项目团队成员定期腾出时间完成项目活动，即使他的日常任务必须暂时转交给 IT 部门的其他成员。

应该让大家清楚地认识到，那些成功参与项目的人是在为组织“多走一里路”，应该得到认可和奖励。成功参与大大小小项目的人，都应该受到特别表扬。正如敏捷世界里所说的，这能把“可能性的艺术”放到恰当的位置上，让组织目标与员工的动力保持一致。
