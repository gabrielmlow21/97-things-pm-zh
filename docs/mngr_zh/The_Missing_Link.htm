缺少的那一环

Paul Waggoner, MBA, PMP, MCSE, CHP, CHSS Waukee, Iowa, USA

软件项目经理一致认为，最难的挑战之一，是让团队成员真正投入项目的细节，把自己的任务和进度牢牢抓在手里。他们明白，团队成员夹在两头之间：一头是日常的运营职责，比如处理日常事务、排除故障、协调部门里的事、回复各种来往沟通；另一头是有时限的项目开发工作。

被选进项目团队，起初可能被看作一种肯定，可很多开发人员觉得，参与项目会让他们没法专心做本职工作。真到了紧要关头，开发人员可能会直言：对他/她来说，日常维护和支持自己负责的系统，比做项目任务更重要。

作为项目经理，如果你的工作得不到、或者别人不肯给它明确的优先地位，你的第一反应会是：这个人不适合留在团队里。可大多数公司的业务专家（SME）人数有限，所以换人，或者另找一个更投入的人，可能根本行不通。

下面几条简单的建议，可以帮你解决这个问题：

  • 确保各级管理层都支持项目的目标。
  • 修改业务专家的职位说明，加上“根据需要担任各项目的团队成员”，而不是只写一句“完成其他分配的工作”。
  • 请管理层和人事部门强调这一变化，并确保所有主管在今后的绩效评估中，把项目工作的成绩看得很重。
  • 每个新项目启动时，由软件项目经理、部门经理或主管、发起人，或另一位重要的相关方，给每位成员发一封专门的邀请，请他们加入项目。这封信或邮件要说明项目的总体目标，以及这位成员的主要职责。
  • 宣布项目顺利完成时，每位成员都会得到一张可以装框的表彰证书；并说明证书的副本会放进他/她的人事档案，在季度绩效评估时作为参考。
  • 部门经理的上司应该明确表示：项目对推进公司目标的作用，甚至比日常的 IT 工作更重要。
  • 高层应该特别要求部门经理，帮项目成员定期腾出时间做项目工作，哪怕要把他的日常工作暂时交给 IT 部门的其他人。

要让大家清楚地知道：成功参与项目的人，是在为公司“多走一里路”，理应得到认可和奖励。不管项目大小，成功参与其中的人都应该得到特别的表扬。正如敏捷圈子里常说的，这能把“可能做到的事”放到正确的位置上，让公司目标和员工的动力保持一致。
