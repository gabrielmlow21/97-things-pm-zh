打造能跑马拉松、而不是只会短跑的团队

Naresh Jain Malad, Mumbai, India

如果你在短时间内用最快的速度跑——用田径的说法就是“冲刺”——你会把自己累垮。要跑马拉松，团队必须有纪律、每天练习，并保持能长久维持的节奏。做软件项目时，我们不想跑一次就筋疲力尽。我们要以稳定的速度一直跑下去。能长期运作的团队，是为跑马拉松准备的，而不是只被允许去冲刺。

做出有用的软件产品，本身并不是目的。团队成员需要学会互相帮忙，帮其他成员发挥真正的潜力，并营造一个让每个人都能超越自己限制的环境。

大多数团队都不知道该怎么做。需要有人主动来填补这个空缺。在大多数情况下，软件项目经理是负责团队成长的最佳人选。我建议项目经理把打造能长期运作的团队当成目标。这是他/她为项目带来额外价值的一个主要方式。

如果项目经理专注于团队建设和个人成长，按时、在预算内交付自然就会做到。这也能确保团队能自我管理，当项目经理要同时带好几个项目时，团队不需要有人看着。

通常，项目经理会被每天的救火工作缠住，所以根本没有时间有计划地打造团队。按照一份长期的团队培养计划来做，最终能让项目经理不用事事都管，不只是在这个项目，在以后的所有工作中都一样。

软件项目管理的重点需要根本地转变，让项目经理扮演更有策略性的角色。把执行层面的事交给开发团队。这样团队会把项目当成自己的事，而软件项目经理就能成为真正的协助者或催化剂，确保整个项目往正确的方向走。

乔治·S·巴顿将军说过：“没有任何计划在碰到敌人后还能照原样执行。”这表示项目经理要花更多时间，让团队有能力应对没预料到的变化，而不是去插手每天的编码和架构决定。如果他们没有编程背景，却以为能骗过 IT 团队、让团队以为自己懂软件开发的细节，那就太傻了。团队马上就会知道他们是不懂装懂。

软件项目经理就像操作系统的内核*。内核本身不做用户要做的事，但它确保在内核上运行的程序能正确地完成用户的任务。同样，如果项目经理能成为真正的协助者和教练，确保团队成员之间合作得最好，那么打造一个能跑马拉松、能交出高质量软件的自我管理团队，就不再是问题了。

  • 系统内核是操作系统的核心部分。它把浏览器、文字处理、表格和电子邮件等应用软件和电脑硬件连接起来。这样，所有应用程序都能使用内存、处理功能和输入/输出设备。
