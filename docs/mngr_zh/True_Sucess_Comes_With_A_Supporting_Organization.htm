真正的成功，来自一个支持你的公司

Cindy Berg, Phd (ABD), PMP Glendale, Arizona, USA

如果一个组织回避风险规划，不主动寻找问题，也不及时解决问题，原因可能出在文化上。项目团队里那些故意唱反调的人，常常被扣上“麻烦制造者”的帽子。如果组织动不动就“迁怒于报信的人”，团队成员就会避而不谈棘手的问题，甚至可能倾向于把项目问题藏起来。

这样的文化氛围会助长互相推诿的风气，损害整个组织、员工个人和客户。软件项目经理的角色，是让项目交付可预测，尽量减少意外。如果没有人及早指出陷阱，往往就会冒出“惊喜”。这些很少是好的惊喜，多半是难看的那种：开发人员把问题捂着不让暴露，根本不可能事先预见、事先规划。

明智的高层会确保公司支持那些能让开发人员发挥效率的态度和行为。这包括审视人事政策和激励计划，确保它们与能打造出过硬产品和服务的行为相一致。

一个典型的不一致的例子是：组织表面上大力“宣扬”团队合作，却一贯奖励个人贡献。人都很精明，知道哪条路对自己最有利。如果高层能让自己声称信奉的东西，与为鼓励高效行为而提供的工作环境保持一致，个人和组织就都能蓬勃发展。

如果你发现自己身处一个不支持你、或者运转失灵的组织，下面是一些你可以采取的步骤：

  1. 不断地问，直到弄清项目的范围，这样你才能在范围之内工作。
  2. 找出可能的团队成员和其他相关方。只要条件允许，就让他们参与头脑风暴、规划和项目执行。
  3. 让真正干活的人充分参与项目的进展更新和决策，至少在他们完成这个项目上的工作之前都要如此。
  4. 始终做一个诚实的软件项目经理。永远不要为了避免冲突或尴尬的讨论，就粉饰问题或把问题简单化。
  5. 在你的项目团队里，营造你希望整个组织都能拥有的环境。

项目经理必须客观地看待项目。他们处在一个吃力不讨好的位置：首先要效忠于付他们薪水的组织，同时又要和开发人员建立信任。如果项目前景黯淡，一个精明而有原则的项目经理，应该建议先取消项目，等外围的问题解决了再说。

我们都希望在一个有统一战略、支持新软件项目开发的组织里工作。可惜，即使在同一个组织里，各部门之间在这方面的能力也可能天差地别。既然朝着更具支持性的环境迈进对大家都有好处，提醒高层注意项目优先级与绩效奖励之间的文化冲突，就应该成为软件项目经理职责的一部分。
