沟通是关键

Gennady Mironov, CPM Toronto, Ontario, Canada

无论哪个行业，项目经理最需要掌握的本事，就是怎样做个好的沟通者。一个人可能有一大堆证书，名字后面跟着一长串头衔和资质，可如果不懂得怎样和别人协作，项目的工作就没法好好完成。

我深信，启动一个新项目时，好的项目经理应该亲自和所有相关方见面，尤其是客户。项目经理应该做个自我介绍，讨论项目目标和所有关键问题。只要相关方、客户甚至项目团队不是分散在不同大洲，就算经济不景气，见个面也不该是什么大问题。

我们俄罗斯有句话：“百闻不如一见。”根据我自己在数百万美元项目上的项目管理经验，我发现只要亲自去拜访客户，往往半天之内就能轻松解决问题。

有一个项目，我们的承包商迟迟不提供我们需要的无线基站，拖慢了项目进度。问题在于，承包商把这部分工作外包给了自己的分包商，而分包商的电源系统交货晚了。我们花了好几个星期打电话、来来回回发了无数邮件，还是没能解决。

最后，我决定亲自去见承包商，讲清问题的细节，提出几个可能的解决办法，终于拿到了需要的设备。大多数情况下，只要你愿意倾听，并帮忙想出合理的办法，客户都会站在你这边，愿意支持你。

还有一次，一位客户坚持要一个非常短的项目工期。他想在年底缩短设备的生产周期，而那时所有工厂都在满负荷运转，想尽量多完成一些订单。我们没法接受，因为这个工期只有标准工期的一半。

我又一次组织了我们公司、客户和供应商的三方会议。我们坦率地提出了最短、但切实可行的工期，并详细解释了为什么没法再压缩。我们还专门做了一次盘点，弄清项目所需的物品中有多少已经有库存，然后冒了点风险，在还没收到客户订单确认的情况下就接下了订单。

最终，我们成功完成了项目，比那个极紧的工期还提前了两天。客户非常高兴，新年伊始又出人意料地给了我们另一个价值 200 万美元的项目。我们满足了进度、范围、预算和质量的要求，这个项目还为公司多赚了利润。

软件项目也一样，靠的是人与人之间的沟通。
