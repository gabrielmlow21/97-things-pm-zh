沟通是关键

Gennady Mironov, CPM Toronto, Ontario, Canada

任何行业的项目经理应该具备的最关键的知识，就是如何成为一个良好的沟通者。这个人可能拥有许多不同的证书，名字后面跟着一长串头衔和资质，但如果不具备与他人协作的基本知识，项目的工作就无法正确地完成。

我坚信，在开始一个新项目时，优秀的项目经理应该与所有干系人亲自见面，尤其是客户。项目经理应该做自我介绍，讨论项目目标和所有的关键问题。如果干系人、客户乃至项目团队不是分布在不同的大洲，那么即使在经济衰退期间，当面会谈也不应该是什么大问题。

在俄罗斯，我们有句话：“百闻不如一见。”根据我自己在数百万美元项目中的项目管理经验，我发现，只要亲自登门拜访客户，我往往半天之内就能轻松解决与他们之间的问题。

在一个项目中，我们遇到了一个问题：我们的承包商没有向我们提供所需的无线基站，拖延了项目进度。问题在于，承包商把这部分项目外包给了自己的分包商，而分包商的电源系统交付晚了。尽管我们花了好几个星期打电话、来来回回发了无数封电子邮件，却始终无法解决这个问题。

最后，我选择亲自与承包商会面，解释了问题的细节，提出了一些可能的解决方案，我们终于拿到了所需的设备。在大多数情况下，只要你愿意倾听，并帮助想出一个合理的解决方案，客户都是站在你这一边的，并且愿意支持你。

还有一次，我们的一位客户坚持要一个非常短的项目工期。他希望在年底缩短设备的生产周期，而那时所有的工厂都在满负荷运转，以尽可能多地完成采购订单。我们无法接受，因为这个工期比标准项目周期短了一半。

我又一次组织了我们公司、客户和供应商之间的三方会谈。我们坦率地提出了最短的、切合实际的工期，并详细解释了为什么无法再缩短。在完成了一次专门组织的盘点、弄清楚项目所需的物品中我们已经有多少库存之后，我们冒了一些风险，在甚至还没有收到客户订单确认的情况下就接下了订单。

我们成功地完成了项目，比那个非常紧张的工期还提前了两天。客户非常高兴，在新年伊始又意外地给了我们另一个价值 200 万美元的项目。我们满足了进度、范围、预算和质量的要求，而且在这个案例中，还通过项目为组织赚取了额外的利润。

软件项目同样依赖于人与人之间的沟通。
